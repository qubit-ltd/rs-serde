# `rs-serde` 设计与实现评审（2026-07-11）

## 结论

`rs-serde` 应保留为独立 crate，但应被正式定位为“轻量 Duration codec 与 Serde adapter”，而不只是属性模块。它已被 `rs-retry`、`rs-progress` 和 `rs-config` 复用，集中维护是有价值的；继续拆成更多 crate 只会增加发布和版本协调成本。

当前最严重的问题是有损的毫秒格式被用于领域状态序列化。重构目标应是精确语义、格式无关的反序列化和轻依赖，而不是继续扩展现有 adapter 的兼容分支。

本评审中没有发现 P0。

## 做得好的部分

- API 很小，`duration_millis` 与 `duration_with_unit` 的用途易于理解。
- `duration_millis` 的整数反序列化严格，且不依赖具体 Serde 格式。
- 单位集合、默认毫秒单位和 Serde 错误映射均已明确实现。
- retry、progress、config 三类不同调用方已证明公共 codec 的复用价值。

## 需要优先修复的契约问题

### P1：毫秒四舍五入会改变合法 Duration

`duration_millis::serialize` 与 `duration_with_unit::format` 均通过 `DataConverter` 把 Duration 四舍五入到毫秒。结果包括：

- `499µs -> 0ms`；
- `1500µs -> 2ms`；
- `42ns -> "0ms"`。

`rs-retry` 的 delay/timeout 只要求非零，因此一个合法值可在序列化后变成非法零值；`rs-progress` 的 elapsed 来自纳秒精度的 `Instant`，对象 round-trip 也无法保持相等。

建议将以下语义明确拆分：

1. exact state codec；
2. strict integral-millis codec，非整毫秒直接返回错误；
3. rounded display formatter，仅用于展示。

当前 adapter 可作为兼容 API 保留，但需要在文档和名称上标明其 lossy 属性。

### P2：`duration_with_unit` 并不适用于所有 Serde format

`src/serde/duration_with_unit.rs` 的反序列化先构造 `serde_json::Value`，这依赖 `deserialize_any`。JSON、YAML、TOML 等自描述格式通常可用，但 bincode/postcard 等非自描述格式会失败，即使序列化端能够写出字符串。

建议用自定义 Visitor 直接读取字符串或整数，并依据 `Deserializer::is_human_readable()` 定义协议；更清晰的做法是区分“始终字符串、可移植”的 adapter 和“字符串或整数、面向配置”的宽松 adapter。

### P2：format 与 parse 的可表示范围不对称

formatter 使用 `u128` 计算毫秒，而 parser 会先将数值限制为 `u64`。接近 `Duration::MAX` 的合法值可以成功 `format`，却无法再 `parse`，破坏 `parse(format(x)) == x` 的基础 codec 契约。

建议用 `u128` 解析数值，再按单位做 checked 换算为 seconds/nanos，并为零值、单位边界和 `Duration::MAX` 添加 property test。

### P2：小 crate 带入了完整 datatype 依赖图

当前仅约两百余行的 crate 依赖 `qubit-datatype` 与 `serde_json`，连带引入日期时间、大数、URL/ICU 等完整图。对于 `rs-progress` 这类只需要 Duration codec 的下游，这是不必要的编译与供应链成本。

建议将 Duration 的整数 parse/format 直接实现在本 crate，移除 `serde_json::Value`；或让下层提供真正轻量、可单独启用的 Duration feature。

## API、错误与测试意见

- `format` 使用 `expect` 依赖上游“永不失败”的实现细节；应直接实现无失败的整数 formatter。
- `parse` 返回 `Result<Duration, String>`，丢失无效数字、未知单位和溢出的结构化分类。应提供 `ParseDurationError`。
- 现有测试主要覆盖 JSON 和整毫秒输入，缺少非自描述格式、sub-ms、半毫秒、极值和真实 retry/progress round-trip。

## 建议的演进顺序

1. 新增 exact 与 strict-millis adapter，并为 retry/progress 选定正确语义。
2. 用 Visitor 取代 `serde_json::Value`，使 adapter 在非自描述格式中可用。
3. 在本 crate 内实现轻量 Duration codec，消除对完整 datatype 图的依赖。
4. 以兼容扩展方式迁移旧 adapter，下一主版本再调整默认 wire 格式。
